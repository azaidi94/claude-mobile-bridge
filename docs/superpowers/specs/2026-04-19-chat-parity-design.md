# Chat Parity (History + Formatting) Design

**Date:** 2026-04-19
**Status:** Approved

## Overview

Fix two pre-existing issues in the Mini App's Chat tab so it reaches parity with the Telegram side of the bridge:

1. **History replay** — Chat tab currently starts blank because it only subscribes to the live SSE stream. Telegram has full chat history per session; the web should too.
2. **Markdown/HTML rendering** — `Terminal.tsx` renders `evt.content` as plain text. `text` events arrive as raw markdown (from Claude); `tool` and `thinking` events arrive as HTML strings (built in `src/formatting.ts` for Telegram's HTML parse mode). Result: asterisks and raw `<b>` tags are visible in the web UI.

## Part A — History Replay

### Backend

New module: `src/web/sessions/history.ts`

```ts
export async function readSessionHistory(
  sessionId: string,
  limit: number,
): Promise<SseEvent[]>;
```

Algorithm:

1. Find the session's JSONL under `{CLAUDE_DIR}/projects/*/{sessionId}.jsonl`. Reuses the dir-scanning approach already in `src/web/tasks/reader.ts:findSessionJsonl`. (Export that helper from reader, or factor both into `src/web/claudeDir.ts` — whichever keeps files clean.)
2. Stream-read the JSONL line-by-line (don't load whole file — transcripts can be megabytes). Parse each line as JSON; skip malformed.
3. Keep only entries with `type === "user"` or `type === "assistant"` and a `message` object. Ignore `attachment`, `permission-mode`, `hook-success`, etc.
4. For each kept entry, convert to zero or more `SseEvent`s (see mapping below).
5. Buffer the last `limit` events (not lines — entries can expand to multiple events). Return in chronological order.

Entry → event mapping (mirrors what `src/handlers/streaming.ts` already emits live):

| JSONL entry                                                | Emitted events                                                                               |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `type:"user"`, `content` is a plain string                 | `{ type: "text", content: "› <string>" }`                                                    |
| `type:"user"`, `content` is array with only `tool_result`s | Skip (noise for chat view — tool output is implied by the assistant's next turn)             |
| `type:"user"`, `content` is array with `text` blocks       | For each text block: `{ type: "text", content: "› <text>" }`                                 |
| `type:"assistant"`, block `type:"text"`                    | `{ type: "text", content: text, segmentId: <stable index> }`                                 |
| `type:"assistant"`, block `type:"thinking"`                | `{ type: "thinking", content: <thinking text, no HTML escaping — client renders> }`          |
| `type:"assistant"`, block `type:"tool_use"`                | `{ type: "tool", content: formatToolCall(name, input) }` — reuse `src/formatting.ts` helpers |

`segmentId` is an assistant-turn-local counter so the client keeps text blocks grouped consistently with the live stream.

### Route

In `src/web/routes/sessions.ts`, add:

```ts
app.get("/:id/history", async (c) => {
  const sessionId = c.req.param("id");
  const limit = parseInt(c.req.query("limit") ?? "200", 10);
  const events = await readSessionHistory(sessionId, limit);
  return c.json({ events });
});
```

Uses existing `authMiddleware` since the router already applies it.

### Frontend

`web/src/api.ts` — add `api.getSessionHistory(sessionId: string, limit?: number): Promise<SseEvent[]>` returning the events array.

`web/src/pages/ChatPage.tsx` — in the `useEffect` keyed on `activeId`, BEFORE subscribing to the live stream, call `getSessionHistory` and seed `events` state. Then subscribe. The live stream continues to append via `setEvents(prev => [...prev, evt])`. No deduplication: history ends at the last journal entry, live events strictly follow.

## Part B — Formatting

**Client-side only.** No backend change. `Terminal.tsx` learns to render the content it already receives.

### Dependencies

In `web/package.json`:

- `marked` (same major version as the root's `marked@^17`) — markdown → HTML
- `dompurify` — HTML sanitizer

### Rendering

In `Terminal.tsx`, replace `{evt.content}` with a sanitized `dangerouslySetInnerHTML`:

```tsx
function eventHtml(evt: SseEvent): { __html: string } {
  if (evt.type === "text") {
    const html = marked.parse(evt.content, {
      async: false,
      breaks: true,
    }) as string;
    return { __html: DOMPurify.sanitize(html) };
  }
  // tool / thinking: already HTML from src/formatting.ts
  return { __html: DOMPurify.sanitize(evt.content) };
}
```

Rationale for safety: content is generated by our own server code (`formatting.ts` or Claude's raw assistant text). `DOMPurify.sanitize` with default config strips scripts/event-handlers, so even if a tool description ever leaked user-controlled HTML it couldn't execute.

Existing prefixes/classes per event type (`⚙`, `…`, styled text) stay in a wrapper `<span>`/`<div>`; only the content is HTML-rendered.

### Visual scope

No new colors, no new layouts. Markdown bold/italic/code should visually match the existing `text-terminal-text` palette. `code` inline and `pre` blocks should use the existing terminal background/border classes.

## Error Handling

- History request fails or JSONL missing → return `{ events: [] }` (never error). Chat behaves like today (blank until first live event).
- Malformed line in JSONL → skip, warn. Stream-reading continues.
- `marked`/`DOMPurify` throw on malformed content → fall back to rendering as plain text (escaped) so the UI never breaks.

## Testing

### Backend

`src/__tests__/web-sessions-history.test.ts`:

- Returns `[]` when JSONL doesn't exist
- Parses a fixture JSONL with user text, assistant text, assistant thinking, assistant tool_use, and noise entries (hook attachments, permission-mode). Asserts the event sequence matches expectations.
- Limit caps the number of returned events to the last N
- Malformed lines are skipped without throwing

### Frontend

`web/src/__tests__/Terminal.test.tsx`:

- `text` event with `**bold**` renders a `<strong>` element
- `tool` event with `<b>Read:</b> foo.txt` renders a `<b>` element with "Read:"
- `thinking` event renders with italic/muted class and preserves inner HTML
- Events with `type: "done"` / `"segment_end"` are skipped

## Out of Scope

- Virtualized scrollback for very long transcripts
- Fetching history for sessions that are not in `getSessions()` (the existing flow already only shows discoverable sessions)
- Attachments / images in history (rare in Claude sessions; revisit if users hit it)
- Client-side reconnect indicator for SSE (noted in kanban spec too; defer)
