## What changed structurally

Quick mental model for someone reading the code afresh:

1. **Routing is explicit through `SessionContext`** — resolved topic-first at the bot edge in `bot.ts`/`callback.ts`, threaded through every handler. No global "current session" pointer. `getActiveSessionName()` survives only as the v1 picker pointer for the web UI; nothing routes through it.
2. **Per-session state lives in `SessionState`** (`src/sessions/session-state.ts`), keyed by `sessionName` in a Map. `runQueryStreaming(state, opts)` and `runPlanApproval(state, opts)` are free functions in `src/session.ts` — they operate on the passed-in state. Two queries can run in parallel against different SessionStates without interfering.
3. **All TG sends go through `MessageBus`** (`src/messaging/bus.ts`). Single log schema `bus.send`, owns parse-mode resolution, chunking, plain fallback, dedup TTL, per-chat rate limit, `silent`, `replyMarkup`. Wired in `bot.ts:setMessageBus(createMessageBus(bot.api))`. Handlers call `getMessageBus().send(...)`.
4. **God files decomposed** — `src/handlers/commands/` (13 files) and `src/handlers/watch/` (19 files), shared state in single homes (`_topicManager`, `offlineSessionCache`, `watches`, `typingState`).
5. **Silent catches eliminated** — `src/utils/safe-async.ts` is the new pattern. ~20 previously-invisible failures now log with stable labels.
6. **TCP backpressure handled** — `src/utils/socket-writer.ts` queues writes and awaits `'drain'` between them. Used by both `relay/client.ts` and `mcp/channel-relay/server.ts`.

## Tips for the next session

- The repo's canonical test runner is `bun run test` (= `test:isolated`). The batched `bun test` exposes cross-test pollution; treat its fail count as noise unless an isolated run also fails.
- The known pre-existing flake on `bun test src/__tests__/scenarios/` (S5 backfill) was fixed in phase 3 — if it re-appears, check `_helpers.setupIsolatedStateDir` idempotency.
- `setupIsolatedStateDir` shares one STATE_DIR across all scenario test files in a process because `paths.ts` caches `STATE_DIR` at first module load. Don't reintroduce per-file `mkdtempSync` + teardown unless you also refactor `paths.ts`.
- `MessageBus.send()` is fire-and-forget for production callers but the test mock pattern in `src/__tests__/watch.test.ts` uses a `_setBusSink(arr)` indirection — copy that for new bus-consuming tests.
- The `cursor-*` synthetic session-id prefix still exists. Phase 5 would unify it; until then, handlers branch via `sctx.source === "cursor"` (cleaner than the prefix sniff that pre-phase-1 used).
